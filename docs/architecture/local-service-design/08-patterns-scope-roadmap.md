# §25–27 模式、边界与分期

## §25 设计模式落点

只列**实际在用**的：每条都得说出它落在哪、解决什么。没有落点的模式不写进文档——罗列不用的模式只是噪音。

| 模式 | 落点 | 解决什么 |
|---|---|---|
| **微内核 / 插件** | Go 核只做 5 件事，web 核只做 5 段 runtime，业务全是 Module/Plugin（§4、§13、§17） | 核心稳定、业务可插拔 |
| **注册表（Registry）** | capability / command / route / view / transport / filter 六类登记簿（§4、§7）；前端同构（§17.1） | 一处注册，多处派生，无第二份清单 |
| **依赖倒置 / DI** | 模块只通过 `ActivationContext` 触碰内核（§5.2）；前端同规（§17.2） | 模块不 import 内核内部包 |
| **端口-适配器（Ports & Adapters）** | 内核定义 `Transport` 端口（§4.3），HTTP/WS/MCP 各是一个模块实现 | 加 N 条触达面 = 加 N 个模块，内核零改动 |
| **管道-过滤器（Pipe and Filter）** | Invoke 管线（§9.3）：身份→校验→权限→可用性→配额→handler；codegen 管线（§11.1）：Go struct→JSON Schema→TS | 有序、可断言、fail-closed |
| **快照 / 不可变（Snapshot）** | 注册表 freeze（§6.1、§17.2）；服务期只读快照无锁并发读 | 消除"能力清单运行中变了"的竞态 |
| **工厂方法（Factory Method）** | 每个模块包导出 `New() Module`，DI 容器按 token 调构造器（§4.1、§5.2） | 构造与装配解耦，模块可单测 |
| **抽象工厂（Abstract Factory）** | `composeHost.{web,electron,rust}`（§19）成套产出「transport + DI 绑定 + 模块集」 | 按宿主装配内核 |
| **单例（Singleton，显式构造版）** | 进程内一份 kernel / DI 容器 / 注册表，由 `main` 构造后注入；**不做**包级 `var` + `init()` | 单测与 `--local`（§22.3）能并存两个内核实例 |
| **适配器（Adapter）** | transport 模块把 HTTP/WS 报文适配成 `kernel.Invoke`（§4.3）；web 侧每宿主一个适配器供 `IChannel`（§18.2） | 加触达面 / 换宿主不动内核与 UI |
| **桥接（Bridge）** | `IChannel` 抽象与 transport 实现各自独立演进（§18） | 两侧都能单独变 |
| **装饰器（Decorator / Filter）** | 三锚点过滤器包装调用链（§9.3 `ctx.Filters()`）；每个 view 外包 ErrorBoundary（§17.3） | 横切逻辑不侵入 handler；一格炸不掉整页 |
| **门面（Facade）** | `IChannel` 是 UI 唯一调用口（§18.1）；`ActivationContext` 是模块看内核的唯一门面（§5.2） | UI 不感知宿主；模块不 import 内核内部 |
| **代理（Proxy）** | `scopedChannel(pluginId)` 按 `requires` 收窄（§17.3，审计闸门非沙箱）；四期能力搬进子进程后原位留转发代理（§28.7） | 越权调用当场拒；拆进程时调用方零改动 |
| **组合（Composite）** | viewContainer → view 贡献物树（§20.4）；内核不为此定义通用接口 | 两级导航由树派生 |
| **策略（Strategy）** | 每宿主一个 transport 策略（§18.2、§19）；能力 `available` 按平台/权限判定（§20.3） | 换宿主 = 换策略 |
| **观察者（Observer）** | event bus（§6.3）、WS 订阅推送（§8.2）、`useCapability`（§20.2） | 解耦广播；可用性变化自动重渲染 |
| **命令（Command）** | `contributes.commands` 是跨插件协作的合法路径（§20.6）；CLI 子命令与命令面板条目由能力派生（§8.3、§22.2） | 插件零直接依赖；CLI 面自动生成 |
| **中介者（Mediator）** | event bus 与 capability 注册表充当模块间中介（不变式 8：零直接 import） | 模块协作不互相 import |

内核**不引**反射式 DI 框架、不为单实现造接口、不引中立 IDL（§4 反面清单、§11.2）。

**风格是约束**（§28，每条都有不变式在 CI 站岗）；**模式只是实现手段**——模式不进 CI，换模式不动不变式。

## §26 明确不做（一期）

- **多真源 / 双写**：单 Go 核，schema 真源只在 Go struct，无 TS→Go 回写（§10、不变式 5）。
- **中立 IDL / protobuf / 双向 codegen**：单向管线够用（§11.2）。
- **外部插件提供后端能力**：一期插件纯 UI（§13、§16）。
- **进程隔离 / 脚本沙箱**：一期无外部后端代码，不需要（§16）。
- **远程插件安装 / 签名校验**：一期固定本地目录扫描（§2）。
- **后台守护化**：一期前台运行（§23.4）。
- **自定义域名**：直接 `127.0.0.1:10312`（§2）。
- **配置热重载**：改配置重启生效（§24.2）。
- **MCP 触达面**：预留第四条派生面，一期不实现（§8.4）。
- **微服务化 / 多进程拆分**：单机单用户，进程内调用零序列化成本，拆进程只增部署与调试复杂度；但 capability + JSON-RPC 本就是一条进程边界，将来真要拆，seam 已经在那里（§28.7）。
- **局域网 / 远程访问**：监听地址硬编 `127.0.0.1`，不暴露局域网（§2）。
- **插件热插拔**：注册表 freeze 后不可变（§6.1、§17.2），装新插件重启服务 / 刷新页面。
- **事件持久化 / 重放**：event bus 只做进程内通知，丢了重查状态（§6.3）。

## §27 分期

| 阶段 | 目标 | 关键新增 |
|---|---|---|
| **一期（当前）** | CLI 起本地服务 + web 承载全部 UI + 内置能力 + 纯 UI 插件 | Go 微内核（5 件事）、web 微内核（5 段 runtime）、三触达面派生、Origin+Host+token 连接闸门（§9.4）、Invoke 管线（§9.3）、注册表 freeze（§6.1）、Go→TS 契约链、CLI 客户端模式（§22）、UI 插件 |
| **二期** | 第四条触达面 | MCP server（tool 列表由注册表派生，§8.4）；MCP 作为又一个 transport 模块接入，**内核零改动**（§4.2） |
| **三期** | 插件运行时扩展 | `ts` / `wasm` 插件 runtime；`rust-builtin` 仅内置 |
| **四期** | 外部后端能力 | 独立子进程 + JSON-RPC 隔离（§16）；子进程侧复用 `Transport` 端口（§4.3），隔离成本随需求才付 |
| **可选** | 部署形态 | 后台守护化（§23.4） |

每一期的隔离/复杂度成本都跟着**真实需求**来，不提前造（§16 尾）。承重墙不变式（1、4、5、7、8、9，见 §3）跨所有阶段必须守住，2、10 是同级安全底线——任何阶段的"特事特办"绕过，评审一票否决。
