# §22–24 CLI、进程与配置

## §22 CLI 是客户端，不是第四种 handler

### §22.1 两类命令，来源不同

| 类 | 命令 | 来源 | 执行处 |
|---|---|---|---|
| **应用管理** | `start` / `stop` / `status` | CLI 专属，手写 cobra 命令 | 本地进程（管进程本身） |
| **能力直调** | `fs read` / `shell exec` … | 从 `Transports.CLI==true` 的能力派生（§8.3） | **转发到运行中的服务** |

**应用管理命令不是能力**——它们管的是进程本身（起停这个 Go 服务），没有对应的 capability，也不进注册表。能力直调则**连到已运行的服务**，走同一条 WS 通道、同一条 Invoke 管线（不变式 2），token 从 `~/.xtools/session.token` 读（§9.4）。

```
xtools start            # 前台启动本地服务（一期），绑定 127.0.0.1:10312
xtools stop             # 通过锁文件里的 PID 发信号停机
xtools status           # 读锁文件 + 探活，报运行状态
xtools fs read --path … # 能力直调：连 WS → kernel.Invoke（派生自 fs.read）
```

服务没在跑时，能力直调**报错并提示 `xtools start`**，不偷偷起一个后台服务（那会出现两个进程各持一份状态）。

### §22.2 命令树在客户端派生

CLI 启动时查 `capability.list`（§8.1），据此建子命令与 flag（flag 从 Input schema 生成）。这样新增能力不需要重新编译 CLI，也不会出现"WS 有、CLI 忘了加"的漂移（不变式 4）。宿主主版本不匹配时 CLI 报错退出，不猜。

### §22.3 `--local`：显式一次性进程内模式

脚本/CI 里没有常驻服务时，`--local` 在当前进程里起一个内核、跑完一次调用就退出：

```
xtools --local fs read --path ./a.txt
```

限制必须显式，**不静默降级**（不变式 6）：`--local` 拒绝订阅型能力（`fs.watch`）与独占资源型能力，报错说明原因。默认路径永远是「连运行中的服务」，`--local` 只在用户明确写出时生效。

`// ponytail: --local 就是复用同一套模块装配跑一次 Invoke，不为它造第二套代码路径`。

## §23 进程管理

### §23.1 锁文件 + PID

`start` 时写锁文件（含 PID、端口、启动时间）到用户配置目录；`stop` / `status` 读它定位进程。启动时若锁文件存在且 PID 活着 → 报"已在运行"退出，不重复起。

### §23.2 端口占用不静默换端口

绑定 `127.0.0.1:10312` 失败（被占用）→ **报错退出**，打印占用提示，**不静默换端口**（不变式：能力边界显式化）。用户可在配置里改端口（§24）。

### §23.3 信号与优雅停机

收到 SIGINT/SIGTERM → 走 §6.2 停机序列（停新连接 → 广播 shutdown → 逆序 Deactivate → 释放监听与锁文件）。有超时预算，超时强制退出并记日志。

### §23.4 一期前台运行

一期 `start` 前台阻塞运行（日志打到终端）；后台守护化（daemonize）留到后续（§27）。`// ponytail: 前台够用，守护化等真有"关掉终端还要跑"的需求再加`。

## §24 配置文件

### §24.1 只读配置，加载期一次读入

配置在启动时读入，运行期只读（`ConfigReader`，§5.2）。格式 TOML，放用户配置目录，缺省即用内置默认值——**无配置文件也能跑**。

```toml
port = 10312                 # 监听端口，默认 10312
pluginDir = "~/.xtools/plugins"   # 插件扫描目录

[fs]
roots = ["~/work"]           # fs 能力的路径白名单（§15.3）

[security]
# Origin 白名单的**追加**项；内置的 127.0.0.1 / localhost / x-tools.localhost 永远在列，
# 三重校验本身不可关闭（§9.4）。每加一项都是放大攻击面——只在自建前端时才加。
allowedOrigins = []

[limits]
callTimeoutMs = 30000        # Invoke 默认 deadline（能力 Limits 可下调，§9.3）
eventQueue = 256             # 每订阅者有界队列长度，满了丢最旧（§6.3）
```

session token 路径固定 `~/.xtools/session.token`（`0600`，每次 `start` 轮换），**不可配**——可配就意味着能被指到共享目录（§9.4）。

### §24.2 可配 vs 硬编

| 项 | 一期 | 说明 |
|---|---|---|
| 端口 | **可配** | 默认 10312 |
| pluginDir | **可配** | 默认用户目录下固定路径 |
| fs 路径白名单 | **可配** | 默认工作根目录 |
| `allowedOrigins` | **可配（仅追加）** | 内置白名单项不可删 |
| 调用超时 / 事件队列 | **可配** | 默认 30s / 256 |
| 监听地址 | 硬编 `127.0.0.1` | 一期不暴露局域网 |
| 主通道 | 硬编 WS | — |
| 三重连接校验 | **硬编开启** | 不提供关闭开关（不变式 10） |
| session token 路径 | 硬编 | 见 §24.1 |

改配置需重启服务生效（一期不做热重载）。`// ponytail: 热重载等配置项真的多到值得再说`。
